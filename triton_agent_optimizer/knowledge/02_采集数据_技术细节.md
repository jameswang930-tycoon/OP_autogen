## 0. 全景: 5 种采集方法 × 用途

| # | 采集方法 | 粒度 | 用途 | 耗时量级 |
|---|---|---|---|---|
| 1 | 通用 msprof | 全 kernel 骨架 | task.json (耗时/launch/API/多kernel) | 分钟级 |
| 2 | msprof op | 单 kernel 深层 | board.json (带宽/引擎/冲突/L2/频率) | 每 kernel 分钟级 |
| 3 | Event 快测 | 端到端 | verify 段1 秒级判门 + 优化循环内进度 | 秒级 |
| 4 | sweep 实测 | BLOCK 候选 | 分块枚举最优 (真机 Event) | 5-10 分钟 |
| 5 | 工业级 Event | 端到端 | 对比基线 (bench_all) | 每候选 ~分钟 |

## 1. 通用 msprof（骨架采集）

### 命令
```bash
msprof --output=<msprof_out> --application='python3 <kernel_op.py>' --ai-core=on
```
- 由 verifier 段2 执行: `KERNEL_LOOP=30` 环境变量 → app 内部循环 30 遍完整运算链 → 一次 msprof 记录 30×N_kernel 行
- 前置: `VERIFY_WARMUP=3` 次裸跑预热（JIT 编译/冷 cache 消化，不计时）

### 产出: op_summary CSV → `task.json`（骨架）
`pipeline_parse_task.parse()` 解析全部 `op_summary*.csv`（★必须合并多文件，只读第一个会漏 kernel → 假"仅 13 行"）：

| 字段 | 内容 |
|---|---|
| `kernel_slots[]` | **优化目标槽位**：按 distinct Op Name 去重（`kernel_name`/`framework`/`launch_count`/`task`） |
| `task` | 首 launch 的 task_type / task_duration_us / block_dim / input_shapes / input_dtypes / pipes_us / transfers |
| `multi_kernel` | op_statistic 每类算子次数/总耗时/占比 |
| **framework 判定** | `name.startswith("aclnn")` = 框架 kernel（torch 数据准备/参考），**非优化目标**，单列 |
| **目标 kernel 判定** | 非 aclnn 即目标 —— **无名单配置**，kernel 没跑起来 = 全空（采集失败信号） |

### 端到端口径（verifier 段2）
- `Σ 目标 kernel Task Duration ÷ loop` = 单次端到端 ns（求和口径）
- ⚠ 历史教训：msprof Task Duration 求和对小 kernel 欠采（假 14x/200x 加速比 bug 根源）→ 欠采防护：行数 < loop 报警"加速比存疑"

## 2. msprof op（单 kernel 深层采集）

### 命令（每 kernel 一次）
```bash
msprof op --kernel-name=<kernel_name> --output=<op_dir> --warm-up=10 python3 <kernel_op.py>
```

### 产出: 8 个 CSV → `board.json`
`pipeline_parse_board.parse()` 提取全部字段：

| CSV 文件 | 字段组 | 关键字段 |
|---|---|---|
| Memory.csv | 主存带宽 | aic_main_mem_read/write_bw → main_mem_read/write_gb_s |
| Memory.csv | 搬运带宽 | aic_l1_*/aic_l2_*/aiv_gm_to_ub/aiv_ub_to_gm_* |
| MemoryUB.csv | UB 带宽 | aiv_ub_read/write_bw_vector/scalar |
| MemoryL0.csv | L0 带宽 | aic_l0a/l0b/l0c_read/write_bw |
| PipeUtilization.csv | 引擎占比 | aic_cube_ratio / aiv_vec_ratio / aic/aiv_mte1/2/3_ratio / scalar / fixpipe |
| ArithmeticUtilization.csv | 计算量 | cube_fops / cube_fp16_ratio / vector_fops / aic_total_cycles |
| ResourceConflictRatio.csv | 冲突 | aiv_vec_bank/bankgroup/total/resc/mte_cflt_ratio, cube/vec/mte1/2/3_wait_ratio |
| L2Cache.csv | L2 | aic_total_hit_rate(%) |

- 解析后 `normalized`（LLM 用关键字段）：带宽 GB/s、引擎占比、冲突率、L2 命中率、roofline 瓶颈类型
- **deep 按 kernel_name 填充到 task.json 的槽位**（`filled_by="msprof op"`）
- 缺 l2_read/write 列 = A2 系合法缺（910B3 无该列）

## 3. Event 快测（verify 段1 + 优化循环内）

### 机制（`verifier._inject_event_timing` / `_event_e2e_ns`）
- **注入**：改写 kernel_op.py，在 `for _ in range(LOOP):` 循环处注入 Event 计时块（不碰源文件，写 round_dir/event_kernel.py）
- **窗口**：`ev_s.record() → for LOOP: body → ev_e.record()`，`elapsed / LOOP × 1000` = 单次 us
- **多窗口 median**：`KERNEL_EVENT_REPS=5` 个独立 Event 对 → median（抗单次抖动）
- **破 L2**：每窗口前**重建输入张量**（新地址 + `_keep` 防 GC 复用地址——否则 caching allocator 复用 → 破 L2 失效，实测虚高比值全 ≈1.0）
- **warmup**：5 次循环（不计时）
- 输出 `EVENT_E2E_US:x` → 乘 1000 = ns（verifier 内部主判据 `e2e_event_ns`）

### 用途
- verify 段1（`verify_fast_gate`）：正确性 + Event 快测 → 不比历史最优快直接 REVERT（省 msprof 几分钟/轮）
- 优化循环内 KEEP 判据：`e2e_event_ns < best_e2e_event_ns`（Event 权威口径）

## 4. sweep 分块实测

### 机制（`sweep_blocks.py`）
1. **候选生成**：L0 硬件约束枚举（L0A/L0B 64KB×0.9、L0C 128KB×0.9、UB 192KB×0.9、grid∈[16,3000]、全 2 幂；conv2d 系 BLOCK_K≥K_OUT、FA bk_min=ceil_pow2(dim)）
2. **runner 生成**：单进程脚本，每候选 warmup 3 + Event 窗口包 LOOP 10 次 ÷10
3. **崩溃续跑**：设备级错误（aclrt/575）→ 新进程续跑剩余候选（新进程 = 干净设备）；连续 2 个设备错误停本轮
4. **增量保存**：每候选写一次结果文件（fatal 杀进程不丢已测）

### 产出: `sweep_result.json`（09_tier3_sweep/ 或 block_sweep/）
```json
{"best_block": [128,64,64], "results": [{"block":[...], "ns":..., "error":...}], "speedup_vs_cur": 1.23}
```
- **最优 BLOCK 写回 kernel_op.py**（比当前快才写）；sweep 结论注入 planner（含 fresh/来源/采纳状态）
- 触发：round1（分块地基）+ tier3（kernel 结构 hash 变化时重扫）

## 5. 工业级 Event 测量（bench_910b3，对比基线）

### 机制（`bench_common.measure_event`）
- **do_bench 同款**：5 次估时长 → warmup 25ms / rep 100ms 时间预算折算次数 → n_rep 个独立 Event 对 → median/min/mean
- **破 L2**：`fn(i)` 轮换 n_buf=32 组输入 buffer（组数×工作集 > 192MB 才真破；小算子破不掉 = 两侧同口径，公平）
- **流水化模式**（`--pipelined N`，默认 10）：每窗口连续调用 N 次 ÷N → host 下发开销隐藏 ≈ 纯设备时间，**与 verify/measure_final_event 同口径**
- 产出: `outputs/industrial_<op>_<mode>_tflops.json`（time_us median / actual_mode / method / pipelined_n）

### 我们侧最终测量（`test/measure_final_event.py`）
- 对最终优化算子注入同构计时（默认流水化 ÷10）→ 自动写回 `bench_all.py OUR_RESULTS_US`
- 注意：`elapsed_time` 返回 **ms** → ×1000 转 us（单位 bug 已修）

## 7. 采集失败判定（重要）

| 现象 | 判定 | 处理 |
|---|---|---|
| 骨架阶段"未检测到任何目标 kernel" | kernel 没跑起来（**编译失败**，非采集问题） | 看 warmup.txt/task_run.txt 尾部 trace → 修 kernel |
| op_summary 行数 < loop | msprof 欠采 或 coder 弄丢 KERNEL_LOOP | 报警"加速比存疑"，verify 不测 Event |
| msprof op 无 OPPROF | 采集失败 | 查 stderr，重试 |
| 设备级错误（575/aclrt）连续 2+ | 设备被污染 | 新进程续跑 / 停本轮 |
| eager/fa 工业级测量失败 | **真问题**（torch_npu 自带必出） | 查 stderr |
| compile/cann-fused 回退 | 正常（torchair/桥库未装） | 标记 ⚠回退，不参与最优 |

## 8. 口径对照表（对比必须同列）

| 口径 | 内容 | 含 host 下发 | 用途 |
|---|---|---|---|
| msprof Task Duration 求和÷loop | 纯 kernel 时间求和 | 否 | 段2 确认（欠采风险） |
| Event 单次（窗口 1 次） | 设备时间线跨度 | 是 | 工业级默认/严格单次 |
| **Event 流水化 ÷N（默认 10）** | 设备时间线跨度 | 否（被流水隐藏） | **verify 优化循环 / 最终测量 / bench_all 默认 —— 三处统一** |
