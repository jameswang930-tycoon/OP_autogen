## 1. coder.py 职责与函数清单

**职责**：读 Plan + 当前 kernel 代码 → 做最小化代码改动。两步策略：**Step 0 确定性替换（首选）→ Step 1 LLM 修复（兜底）**，全程 Unicode 清洗 + 语法校验 + 防截断 + 防 no-op，失败时回填失败案例库。

### 函数清单

| 函数 | 核心逻辑 |
|---|---|
| `_load_coding_guide()` | 读 `docx/CODING_GUIDE.md` 前 4000 字符；不存在返回空串 |
| `_build_system_prompt(plan_text, tier)` | 组装 system：tier 1~6 映射 `docx/playbook_tier{N}_*.md`（tier6 默认空）；**IRON RULES 5 条**：①只改指定 kernel 文件（尤其不碰 `input/<op>/kernel_op.py` 源文件）②不写 `num_warps/num_stages` 进 `@triton.jit` ③不新增 import、不改函数名/参数 ④输出完整代码不带 markdown 包裹 ⑤old_code 找不到必须报告、绝不猜改 |
| `_build_user_prompt(...)` | previous_error 注入时截断 ≤1000 字符, 附 ★只读参考严禁抄写警告（针对弱模型把 `vsel` 等带英文单引号的解释文本抄进代码 → unterminated string literal）；`kernel_path` 存在时**只给路径让 nga 自己读**（不内嵌代码）, 否则内嵌前 2500 字符 |
| `_validate_python(code)` | `compile(code,"<kernel>","exec")`；失败时返回出错行真实内容 repr（≤150 字符）——修复"只看行号不知该行内容" |
| `_sanitize_unicode(text)` | ①先 `_fix_quote_chars` ②15+ 类 `_UNICODE_FIXES` 替换（dash/引号/空格/数学符号×÷−≤≥∞/箭头/中文标点/框线 ═│/全角数字字母/零宽字符）③千分位逗号归一正则 `(?<!\w)\d{1,3}(?:,\d{3})+(?!\w)`（防 `1,024` 前导零 SyntaxError, 不误伤 `(64, 64, 32)`）④兜底：compile 仍失败则逐行清非注释行非 ASCII（`_closest_ascii` 映射, 未知字符删除）, 清洗后再验证一次 |
| `_fix_quote_chars(text)` | 智能引号两难：场景 A 定界符（需替换 ASCII）、场景 B 字符串内容（需删除）——生成删除版/替换版两个候选, 取先 compile 通过者 |
| `_preserve_header(text, original)` | 原代码前两行有 shebang/coding 声明而清理后丢失 → 从 original 补回（coding 必须在前 1/2 行才有效） |
| `_extract_changes(plan_text)` | 剥 markdown 围栏 → 取首 `{` 到末 `}` → json.loads → 返回 `changes[]` |
| `_apply_plan_changes(code, changes)` | 逐条：new_code 先 `_sanitize_unicode`；`code.count(old)>1` 打 D4 警告（同名 kernel 防误伤, 全部替换）；精确匹配 → replace 全部出现处；容错：单行 old_code 未匹配时按行 strip 归一化（含 CRLF）, 保持原行缩进+原换行符替换；多行只走精确匹配。返回 `(code, applied, missing)` |
| `_generate_diff` / `_count_lines_changed` | difflib.unified_diff；加减行计数（排除 `+++`/`---`） |
| `_dump_failed(code, kernel_path, why)` | 失败留证：坏代码写 `round_dir/failed_kernel.py`（不覆盖 kernel_op.py）, 永不抛异常 |
| `CoderAgent.apply(...)` | 主流程 5 步（见下） |
| `_call_llm(...)` | previous_error 时先查失败库：`retrieve(tier, err, "")` + `format_for_coder` 注入（只读标注）, 再统一走 `LLMClient`（stub 时直接返回原码）, system 前置 `先调用 skill: skills/triton-op-coder/SKILL.md` |
| `_clean_output(raw, original)` | ①去 BOM+行首空白 ②**先**剥 ```python``` 包裹（注释强调必须先于去行首垃圾, 否则包裹被垃圾正则吃掉）③行首垃圾切到 `#/import/from/"""//@triton/class/def` ④`_sanitize_unicode` ⑤`_preserve_header` ⑥长度 <10 或与原文相同 → 返回原码 |
| `_is_noop_change` | 空白归一化后比较（`re.sub(r'\s+',' ')`） |

### apply() 流程（5 步）
- **Step 0**（无 previous_error 时）：提取 changes → 有 missing 直接失败返回（提示 planner 输出精确 old_code）→ 有 applied → 语法校验 → 通过即返回（**不调 LLM**）
- **Step 1**：LLM（异常→不崩循环, 返回原码+报错）；stub 返回原码
- **Step 2**：clean
- **负正闭环回填**：若 previous_error 且代码已变 → `mark_solved(tier, previous_error, ...)`
- **Step 3**：语法校验失败 → dump_failed
- **Step 3.5** 防截断：原码所有 `def` 必须在输出中
- **Step 4**：no-op 检查
- **Step 5**：生成 diff 返回 `CoderResult(success, optimized_code, diff, lines_changed, error_message)`

### 如何保证只改 kernel 区（4 道防线）
1. **IRON RULES 第 1 条**（prompt 层约束）
2. **scheduler 的 `current_kernel` 只指向 `round_dir/kernel_op.py`**（合并单文件）, 源文件 `input/<op>/` 永不写入
3. **Step 0 的 old_code 精确匹配机制**——找不到就失败, 杜绝猜测
4. **"不新增 import/不改函数签名"铁律**（rule 3）

## 2. analyzers/merge_single_file.py（三文件合并, 116 行）

合并对象：`triton_kernel.py`（算子, 原样内联不解析不重写）+ `config.json`（场景/block 配置注入）+ `test_*.py`（测试驱动）。

- `_find_test_file`：排除 `triton_kernel.py`/`kernel_op.py`/`__pycache__`, 优先 `test*` 前缀, 兜底任取非 kernel .py, 再兜底 `test.py`
- `_strip_imports(src)`：删除 `from triton_kernel import X`、`sys.path.insert(...)`、`BLOCK_* = ...` 赋值行、`DTYPE = ...` 行、重复 import（`_DUP_IMPORTS` 正则覆盖 os/sys/torch/torch_npu/triton/triton.language）
- `_config_injection(config)`：`scenario.M/N/K` → `os.environ.setdefault("MATMUL_{var}", val)`；`DTYPE = torch.<dtype>`（默认 float32）；`kernel_config.block_params` 每项生成 `K = V` 常量行
- `merge(op_dir, out_file)`：拼接顺序 = 固定 header（含 imports）+ injection + `# 算子内联` + kernel_src + `# 测试驱动` + test_src

**冲突处理规则**：test 硬编码的 BLOCK_*/DTYPE 一律删除（以 config.json 注入为准）, 重复 import 去重, `from triton_kernel import` 删除。

## 3. scheduler.py 的 coder 链路

- `_code()`（:1033）：读 `current_kernel` 原文 → `CoderAgent(use_llm)` → `coder.apply(original, plan.plan_text, prev_err, plan.tier, kernel_path=round_dir/kernel_op.py)`；任何异常（含 LLM 超时）→ 沿用原码、本轮失败；**diff.patch 只在 success 或文件不存在时写**（防止失败重试把同轮成功 diff 抹成 no-change）
- **轮内重试循环**（:1832-1962）：最多 3 次 attempt, `attempt_log` 每轮重置（轮内上下文, 不跨轮）。`change_s = _summarize_changes(plan)`（"BLOCK_M,BLOCK_N,BLOCK_K=64,64,64" 式梗概, 按第一个 `=` 切 LHS/RHS, 截断保括号成对）
- `build_retry_context(attempt_log, code_err, tier, kernel_name, "code", rn)` 在 coder 失败时调用 → prev_err 累积；verify 失败用 stage="verify" 再调一次 → 回传 coder 同轮改
- `_is_device_error(prev_err)` 命中 → 标记设备污染, 下轮采集前重置设备
- **mark_solved 回填**（:1940-1946）：`kept and attempt_log`（本轮最终成功且之前失败过）→ `mark_solved(tier, attempt_log[-1].get("err"), change_s)`；随后 `prev_err = ""`（防 history 记旧错误, planner 误判成功轮有错）
- 3 次全失败 → `v = {ok:False, speedup: prev_speedup}`（★防假 1.0 掉点 + no_improve 误计）, 错误已在 prev_err → 进 history
- **input 链不变量**：轮首快照 `_pre_round_kernel`/`pre_code`, 未采纳时回滚；同路径时用内容快照恢复并另存 `failed_kernel.py` 留证

## 4. memory/failed_cases.py（333 行, 失败案例库）

**分库**：`memory/tier{N}_failed_cases.json`（N=1~6）。

### API 清单
| 函数 | 核心逻辑 |
|---|---|
| `cases_path(tier)` | tier 文件路径 |
| `normalize_error(err)` | 截 800 字符 → 去 hex 地址/`line N`/`:N:N`/`.py` 路径/纯数字 → 提取英文词（≥4 字符, 过 50 词停用词表, 取前 20）+ 中文片段（≥2 字, 取前 8）→ 去重拼签名 → **sha1[:12] 指纹**。异常时返回空签名 + 指纹 `"000000000000"` |
| `classify_error(err)` | **四分类**（统一入口）——`env`（超时/采集失败/欠采/device reset/npu-smi/连接失败/漏采/无法启动/terminated）> `code_compile`（syntaxerror/unsupported op/not implemented/mlir/vsel/编译失败）> `code_numeric`（result check/mismatch/correctness/atol/rtol/nan/inf/数值/校验失败）> 兜底 `code_runtime`。优先级 env > compile > numeric > runtime |
| `is_code_error(err)` | != env 即真 |
| `load(tier)` / `_save(tier, cases)` | JSON 读写, 损坏→空列表, 永不抛。**LRU 上限**：超 `MAX_CASES_PER_TIER`(50) 时按 `updated_at` 升序淘汰最久未更新的 open/stuck 条目；无 open/stuck 时截尾保留后 50 |
| `_find(cases, fp, stage)` | **判定键 = (fingerprint, stage)** 双键命中（tier 由文件隔离, 完整键含 tier） |
| `record_failure(tier, stage, err, op, change_summary, rn)` | env 类不入库；无签名不入。命中：attempts+1、updated_at、error_class 刷新、related_rounds 去重、attempted_solutions 按 `change_summary 子串包含` 去重追加（截 200 字符, **只留最近 3 条**）；**solved 后再现 → 降级回 open**（solution=None、attempts 重置 1、stuck_at 清空——"没根治"语义）；open 且 attempts≥STUCK_AFTER(3) → **stuck** + stuck_at。未命中：新建完整 open 条目 |
| `retrieve(tier, err, op="", fallback_all=False)` | **两级检索**——L1 指纹精确命中 +100 且 hit_count+1；L2 关键词交集 ≥2 个 +交集数×10；同 op +5；solved +3；排序取前 3。miss 且 fallback_all → 跨 tier 1~6 递归兜底。_save 落 hit_count |
| `format_for_coder(hits, tier)` | 注入文本——solved：`[已解决/op/R/类型] 错误→修复`（solution ≤150）+ 参考补丁（fix_diff ≤150）；stuck：`[★此路不通] 已试 N 次` + 已试方案列表 + `★禁止原样重试上述方案`；open：`[未解决] 已试 N 次` + `可换新方案, 勿原样重试` |
| `mark_solved(tier, err, solution, fix_diff="")` | 按指纹标记所有命中条目 solved, solution/fix_diff 各截 400, hit_solved+1 |
| `build_retry_context(attempt_log, new_err, tier, op, stage, rn)` | ①历次 `【第N次尝试】改动/结果` 全序列（change ≤120、err ≤400 字符）→ ②"──以上尝试均失败 ★禁止原样重试──"分隔线 → ③`【第N+1次结果】new_err 前 600` → ④非 env 时**先 retrieve 再 record_failure**（★防"首犯自命中"）→ ⑤**负正闭环**：本轮 change 摘要与优秀案例库各案例 changes[:2] 的 old+new 拼串去空格前缀匹配（len≥6 且 `_c[:40] in _t2`, 同 op 或 op 为空）→ 提示"该方案曾在 R{round} 成功 (Xx→Yx), 本次失败可能因上下文/尺寸/环境不同——可对比勿原样重放" |

### 生命周期状态机
```
open ──attempts≥3──→ stuck   （只封旧方案, 不堵新思路）
open ──mark_solved──→ solved （成功修复回填）
solved ──错误再现──→ open    （attempts 归 1, 防"假根治"）
```
**去重键结论**：库条目去重键 = `error_fingerprint + stage`（tier 分文件）, **不是 change 指纹**；方案历史仅存于 `attempted_solutions`（按 change_summary 子串去重、保留 3 条）。

## 6. 已知坑与注释警告（完整保留）

1. 弱模型会原样抄参考方案（含 `vsel` 单引号英文）→ unterminated string literal；"只读参考严禁抄写"需保持
2. `_clean_output` 中 markdown 剥离必须先于去行首垃圾；coding 声明补回只处理前两行
3. 引号两难（定界符 vs 字符串内容）用双候选 compile 裁决；千分位逗号正则边界严格防误伤元组
4. D4：old_code 多出现处全替换, 只想改一处须带函数上下文；F5：自测 plan 必须带 changes[], 否则 stub no-op
5. 兜底清非 ASCII 可能引入新错（全角数字被删 → `= , 64`）, 故清洗后须再验证
6. scheduler：stub 假 PASS 只允许 `use_llm=False`；verify 生产异常必须 FAIL 否则真实失败伪装成无改进轮；Event 口径为决策主依据（msprof 欠采毒 best）；首次有 Event 必须对比基线（防假快轮进链）；diff.patch 只成功时写；promote 无 evidence 拒绝；3 次失败用 prev_speedup 防假掉点
7. failed_cases：先检索再入库（防首犯自命中）；solved 再现降级 open（防"假根治"）；env 类不入库（scheduler 自处理设备重置）；永不抛异常（损坏重置）；单进程无锁
8. 跨文件复用：scheduler 直接 `from agents.coder import _extract_changes`（同一实现不重复维护）
9. `kernel_path` 只传路径让 nga 自己读文件（省 token）, 但 `previous_error` 仍内嵌 ≤1000 字符——两者叠加是 prompt 主要 token 来源
