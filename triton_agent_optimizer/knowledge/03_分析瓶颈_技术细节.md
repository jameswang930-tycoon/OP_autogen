## 1. 完整数据流（采集 → diagnosis.json → planner_context.json）

```
input_dir/kernel_op.py
  │ ① 预热裸跑（warmup.txt, 防 JIT/冷启动污染）
  ▼
[阶段1] 通用 msprof --ai-core=on → mindstudio_profiler_output/
  └─ pipeline_parse_task.py → 05_task/task.json（骨架: kernel_slots[] 每 distinct kernel）
  │   从 task.json 取 distinct kernel 名 → 逐个跑 `msprof op --kernel-name=X`
  │   （默认跳过 aclnn* 框架 kernel; FORCE_ALL_KERNELS=1 可放开）
  ▼
[阶段1b] 每 kernel 一个 OPPROF_*/ 目录（8 CSV）→ pipeline_parse_board.py → 04_board/board_<i>.json
  ▼
[阶段2] integrate.py task.json + board_*.json → 06_diagnosis/diagnosis.json
  │   （kernel 名匹配, kernels[i].deep 填充, filled_by 标记; 无 board 时骨架保留）
  ▼
[阶段2.5] run_optimize.sh 内联脚本调 scheduler.extract_tier_fields → 07_tier{N}_fields/{tier{N}_fields.txt, .json}
  ▼
[阶段3] N_KERNELS>1 且 TIER=2（或 ENABLE_HIVM=1）→ bishengir-compile → 08_fusion/hivm_try.txt
  └─ filter_hivm_for_fusion.py → 08_fusion/hivm_fusion_view.txt（融合视图, 给 LLM）
  ▼
[scheduler] _run_optimize（读 diagnosis.json, 无目标 kernel 视为采集失败）→ _diagnose（复用/兜底写 07）
  → _plan: Amdahl 优先级 + build_planner_context → planner_context.json（planner 直接读）
  → 每轮结束: _diag_snapshot → history["diag"] 紧凑串（planner 看趋势）+ diag_snapshots.jsonl（审计）
```

### 各环节字段契约

| 文件 | 结构 |
|---|---|
| `task.json` | `meta / execution_summary(num_kernels, num_kernels_total, total_ns, num_cores) / normalized{kernel_slots[], api_overhead[], l2_hit_rate, framework_kernels[], multi_kernel[]} / raw` |
| `board.json` | `meta / execution_summary(kernel_name, total_ns, num_cores, freq_mhz, rated_freq_mhz, mix_block_dim) / raw{8 CSV 全列全行} / normalized{engine_utilization, bandwidth_gb_s, compute, l2_hit_rate, conflict, traffic_kb, bw_usage_rate, active_bw_gb_s, icache_miss_rate}` |
| `diagnosis.json` (schema v4.0) | `meta(filled_kernels, inputs) / summary / api_overhead / multi_kernel / framework_kernels / kernels[]`；每 kernel: `kernel_name / task{task_duration_us, task_type, block_dim, pipes_us, est_bytes_in/out, transfers} / launch_count / deep{roofline, bandwidth_gb_s, traffic_kb, bw_usage_rate, active_bw_gb_s, icache_miss_rate, engine_utilization, compute, conflict, l2_hit_rate, freq} / filled_by` |
| `planner_context.json` | `tier / config_constants / summary / kernels[](含 time_us_total=单次耗时×launch_count, time_pct) / top_time_kernels[:5] / trajectory_state / history(compact 20轮, 含 diag) / handoff / fusion_analysis / tier3_sweep`；仅 tier==2 附加 api_overhead/multi_kernel/framework_kernels（省 context） |

## 2. 各文件职责与关键函数

### 2.1 analyzers/integrate.py（骨架+deep 整合）
- `_load_measured_peaks()`：读 `bench_910b3/hardware_peak.json` 的 `peak`（run_bench.py 多变体取 max 实测）；异常静默回退理论值
- `_classify(mem_util, comp_util)`：roofline 判型（见 §3）
- `build_deep(bd)`：board.json → deep 子对象（roofline 计算核心）
- `integrate(task_p, out_p, board_paths)`：按 kernel_name 建 deep_map → 逐 slot 填 deep + `filled_by="msprof op"`；**P2 搬运冗余倍数** `traffic_redundancy_read = 实测 main_mem_read_kb×1024 / task.est_bytes_in`（两侧都非空才算，>1.5 为 Tier3/4 重复搬运判据）；写 summary（api_overhead_total_us = Σapi_overhead.total_us）

### 2.2 analyzers/check_fields.py（字段覆盖检验）
- `BOARD_EXPECT`：30+ 期望字段 → (工具, 文件, 具体列名, 子串匹配键[, 排除键])，覆盖 bandwidth/engine/compute/conflict 四节
- `BOARD_EXPECT_NORM`：P2 官方实测字段（traffic_kb/bw_usage_rate/active_bw/icache）用规范化列名**精确匹配**（防 GM_to_L1 vs L1_to_GM 子串误配）
- `_is_na(v)`：空串/NA/N/A/nan/none/-/null 均视为无数据
- `raw_cols_exist(raw, csv_name, keys, exclude)`：文件里有匹配列**且 rows[0] 值非 NA** 才算（列在但值 NA → 合法缺, 不误报）
- `check_board/check_task/check_diag`：判定 OK / 列名不匹配(⚠, 需修 parser) / 合法缺(·)；退出码 1 = 有列名不匹配

### 2.3 analyzers/pipeline_parse_board.py（msprof op 8 CSV → board.json）
- `find_opprof(base)`：base 可直接是 OPPROF 目录或父目录（glob OPPROF_*）
- `read_csv_all`：全列全行保留，列数不符的行用 col{i} 兜底
- `_f(v)`：文本→float，NA 集合→None
- `_first(rows, *keys)`：rows[0] 多子串匹配取列值
- `_norm_col(c)`：去 `(...)` 括号块（单位/estimate 后缀）+ 去空格 + 小写
- `parse(base)`：主函数——Block Dim 防误匹配 Mix Block Dim（`_norm_col=="blockdim"` 精确匹配兜底）；engine_util 7 引擎（cube/vec/mte1/2/3/scalar/fixpipe, fixp 兼容 fixpipe）优先 ratio 否则 time/dur_us 兜底；`active_bw` 从 PipeUtilization 取（列名带 (GB/s) 后缀，**不除 1000**）；bandwidth 从 Memory/MemoryUB/MemoryL0 三 CSV 取 18 路；conflict 原始列名 + `_CFL_NORM` 规范短名双保留（wait 系列 aic/aiv 同名取 cube 侧优先）

### 2.4 analyzers/hivmir_analyzer.py（HIVM IR 静态分析）
- `HIVMIRParser.parse(mlir_text)`：先查 `hivm.hir.\w+` 有无 → 有走格式 A（真实 HIVM dialect）否则格式 B（lowered call @load_gm_to_ubuf_*）
- `_parse_format_a`：逐行识别 memref.alloc（`_try_parse_alloc` 支持 1D/2D/3D, 动态维 size_kb=0）/ 同步 op（set_flag/wait_flag/pipe_barrier/sync_block, engine="Sync", 与 simulator 对齐）/ 跨多行 hivm.hir op（收集到 outs(...) 完整）
- `_try_parse_hir_op`：`ins(...) outs(...) [{attrs}]` 正则；load→gm_to_ub、store→ub_to_gm、matmul 族保留原名；size_kb 优先 alloc_sizes 否则从 tensor<MxNxdtype> 算；attrs 解析 a_transpose/b_transpose/block_sizes
- `_analyze_dependencies`：按 buffer 名的 last_write/last_read 追踪 RAW/WAR/WAW
- `HIVMIRAnalyzer.analyze/analyze_file/to_dict`：`per_op_statistics[]`（29 字段 schema, msprof 字段全为"待补充"）+ buffers + dependencies_summary；自带 5 个自测用例（含真实 matmul: mmadL1 + cbuf/cc 地址空间）

### 2.5 analyzers/filter_hivm_for_fusion.py（融合候选筛选）
- `keep_line`：前缀白名单 `func.func/memref.alloc/hivm.hir./hivm.set_/wait_/pipe_/sync_`，黑名单 arith./scf./tt./llvm./tensor. 等
- `_collect_pipe_us(board_paths)`：从 board raw.PipeUtilization 提取 `*_time_us`（同 pipe 多 board 取 max = 该通路总忙时间近似）
- `_op_pipe_us(op, pipe_us)`：op_type+buffer 区域 → pipe 耗时映射（load 到 L1→aic_mte2、到 UB→aiv_mte2；store 源 L0C→aic_mte3/fixpipe、UB→aiv_mte3；cube→aic_cube_time_us/mac_time_us；VecUnit→aiv_vec_time_us）
- `build_time_note`：每 op 估算耗时占比（分母 = 最忙 pipe 耗时 ≈ 关键路径近似），附融合优先级指引
- `main`：过滤 + 追加依赖清单 + 耗时占比 + 读法指引（含 UB 容量 192KB 检查）

### 2.6 analyzers/pipeline_schema.py
- `OP_FIELDS`（29 字段统一 schema, 三源同形, 无字段=None 待 merge）、`empty_op()`、`make_report(source, input_files, summary, ops, ...)` 产出统一 report（meta/execution_summary/per_op_statistics/engine_utilization/dependencies_summary/parallelism/critical_path/buffers/notes）

### 2.7 agents/scheduler.py 诊断部分
- `TIER_FIELDS`：6 tier 共 ~58 条 JSON path→中文说明；`GLOBAL_FIELDS`（num_kernels/num_kernels_total/api_overhead_total_us 前层信号）；`TIER_PER_KERNEL`（每 tier per-kernel 关键指标, 解决 `_get("kernels[].x")` 只取第一个 kernel 的致命缺陷）
- `_get(d, path)`：`a.b.c`/`kernels[].x.y` 取值, 精确键→子串匹配兜底
- `_diag_snapshot(diagnosis)`：per-kernel `{pct, bn, cu, mu, l2, redun, eng top2}`，**pct = 单次耗时×launch_count/total_us**（防 QKV 复用 3 次被低估 3×）；永不抛
- `_diag_compact(snap)`：按 pct 排序取 top2（top1 欠采时 top2 字段更全, 趋势不丢）→ ~120 字符紧凑串进 history["diag"]
- `extract_tier_fields(diagnosis, tier)`：全局摘要 + 每 kernel 一行概览（占比 ×launch_count）+ 本层附加字段（剔除 kernels[/summary. 前缀避免重复）；`_label.endswith("_B")` 时字节→MB
- `build_planner_context(...)`：完整数据上下文 JSON；`_sanitize_for_ctx` 递归去 None/空、串截 200、列表截 20、深度 6；`_compact_history` 去 changes_full、error 截 60、限 20 轮（GLM5.1 预算 ~20k tokens）
- `_run_optimize(round_dir, tier)`：调 run_optimize.sh 传 `TIER` env 与 M/N/K（**从 kernel config 提取, 防 512 默认覆盖尺寸造成 64× 虚假加速比**）；流式打印；diagnosis 无目标 kernel（coder 改崩）→ 采集失败
- `_diagnose`：**O1 复用 run_optimize 已产出的 07 文件**（校验含"Per-Kernel 概览"字样），缺失才自算兜底

## 3. roofline 瓶颈判定算法（integrate.py）

- **achieved_mem = main_mem_read_gb_s + main_mem_write_gb_s**（★C3: 原 max 只取单向, 写多读少时访存利用率/算术强度被低估）
- **achieved_compute = (cube_fops + vector_fops)/1e12**
- **mem_util = achieved_mem / PEAK_MEM_BW**（1638.4 GB/s 理论 HBM2e, 或 hardware_peak.json 实测）
- **comp_util = max(comp_util_fp16, comp_util_fp32)**（fp32 峰值 = fp16/4, 用 max 防 fp32 高占用被 fp16 峰值低估成 20%）
- **判型阈值**：`mem_util≥0.8 且 comp_util<0.5 → memory_bound`；`comp_util≥0.8 且 mem_util<0.5 → compute_bound`；`mem_util<0.3 且 comp_util<0.3 → latency_bound`；其余 balanced
- **arithmetic_intensity = achieved_compute×1e12 / achieved_mem / 1e9**（mem 为 0 时 None）

## 4. 归一化规则汇总

| 字段 | 规则 |
|---|---|
| Memory/MemoryUB/MemoryL0 带宽 | CSV 为 MB/s；**v≥1000 才除 1000 → GB/s**（★bug 修复: 原 ≥1e4 漏掉 [1e3,1e4) 即 1~10 GB/s 中小 kernel, 曾记成 1000× 高 → mem_util 490%+ 误判 memory_bound） |
| active_bw（PipeUtilization） | 官网单位就是 GB/s, **不换算**（口径不同于 Memory.csv 的 MB/s） |
| bw_usage_rate (%) | `val>1 → /100`（0~1） |
| l2_hit_rate (%) | `val>1 → /100`（0~1） |
| engine 利用率 | 优先 ratio 列, 无则 time/dur_us 兜底, round 4 位 |
| traffic_kb | Memory.csv `*_datas(KB)` 规范化列名精确匹配, 保留 KB |
| conflict | 原始列名 + 规范短名双保留；`_CFL_NORM` 的 wait 系列 aic/aiv 同名 → 优先 aic（cube 侧） |

## 5. HIVM 分析产出的用途（融合候选）

- `hivmir_analyzer` 是**纯静态 IR 分析**（无需 NPU）：产 op 序列（含 sync op）+ buffer 生产/消费关系 + RAW/WAR/WAW 依赖。msprof 运行时字段全是"待补充"占位
- `filter_hivm_for_fusion` 把**静态依赖 + 实测 pipe 耗时**接起来：
  - 融合候选 = RAW 链上相邻的逐元素 op（vadd/vmul/...）且中间无 GM 写
  - 优先级 = **每 op 耗时占比（op 估算耗时/最忙 pipe 耗时）**, 先融合占比最高的链
  - matmul 占大头 → 融合收益在 epilogue；vec 占大头 → 减 GM 往返；WAR → 分配独立 buffer 解锁并行；UB 容量约束 192KB
- `run_hivm_fusion.py`（Tier2 scheduler 路径）：nga run 调 triton-op-fusion skill → `fusion_analysis.json{fusion_candidates[]}` → 进 planner_context 的 `fusion_analysis` 键（多 kernel 且 Tier2 时每轮）
- run_optimize.sh 的 08_fusion/hivm_fusion_view.txt 是另一条（解析期）产物, 供 LLM 直接读

## 7. 已知坑与注释警告（审查完整保留）

1. **PEAK 默认值**：旧硬编码 1800 GB/s 是错的 → 已改 1638.4（HBM2e 4×1024bit@3.2Gbps）；官方标称 313 TFLOPS@1.91GHz vs 推导 294.9@1.8GHz（~6% 差异, 注释明示）
2. **带宽单位 bug**（已修 `≥1000`）：中小 kernel 1~10 GB/s 曾记 1000× 高
3. **M/N/K 尺寸覆盖 bug**（已修）：run_optimize 默认 512 曾覆盖源码 2048 → 64× 虚假加速比；现只在显式传参时导出 MATMUL_*
4. **`_get` 子串匹配歧义**（P1 已修）：conflict 加规范短名（cube_wait/vec_wait/mte*_wait）消除歧义
5. **采集失败必须视为失败**：无目标 kernel（coder 改崩）不得静默回退 matmul_kernel, 否则掩盖崩溃真因；诊断靠 warmup.txt/task_run.txt 尾部 + `_is_device_error`（先排除编译期错误签名 `_DEV_ERR_EXCLUDE`, 防 vsel 坏代码被误标设备污染）→ 设备重置 `_reset_device()`
6. **launch_count 口径**：占比必须 ×launch_count（attention 的 matmul_kernel 被 QKV 复用 3 次）
7. **diag 快照 top2 策略**：top1 字段欠采时 top2 字段更全, 趋势不丢；紧凑串限 ~120 字符入 history
8. **sweep 缓存过期防御**（B1/B4）：缓存 sweep 结果不能当"已穷举最优"禁止调 BLOCK
9. **max_rounds 失效 bug**（已修）：promote 轮免费额度只给真过晋升门的轮
10. **run_optimize.sh 的 `$?` 时序 bug**（已修）：`find|wc` 后取 $? 恒为 0, 必须先存 msprof 退出码
11. **bishengir 把 hivm.hir 打到 stderr**：run_hivm_fusion 必须合并 stdout+stderr 查
12. **msprof op 崩 AICore**：gather/非连续寻址深度 profiling 会崩 → 设备污染级联, 需 grep 设备签名跳过剩余 kernel 并重置
13. **no-op 检测与设备轮次计数**：重试不消耗轮数预算（continue 前先回退 total_rounds）
14. 其余：check_fields"列名不匹配"= parser 键与真机实际列名不符需修 parser（与"合法缺"区分以 rows[0] 值非 NA 为准）；`ub_read_bw_mte` 仅推理产品有（910B3 合法缺）；`aic_mte1/mte2_active_bw` 需 `--aic-metrics=MemoryDetail`（合法缺）；`initial_tflops` 若 cube_fops 是 MAC 计数则约为 FLOPs 一半（显示偏低 2×, 时间口径不受影响）
