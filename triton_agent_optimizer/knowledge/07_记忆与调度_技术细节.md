## 1. Scheduler.run() 主循环完整流程

入口：`python main.py input/<op> [--max-rounds N] [--target X] [--stub] [--fresh/--resume/--sweep-blocks/--sweep-quick]`

**初始化**：读 `outputs/<op>/optimization_trajectory.json`（`_load_traj`, `v!=4` 重置）；`--resume` 且 state 有 `current_kernel` → 续跑（缺键 `setdefault` 兜底），否则 `_reset_state` 从 tier1/round1 重来, 并把源 kernel 存为 `baseline_kernel.py`。`use_llm=True` 时先 Warm-up 一次 nga run。

**主循环条件**：`while (total_rounds - promote_budget) < max_rounds`（total_rounds=真实执行轮含 promote, promote_budget=免费晋升轮数 → 预算按"有效优化轮"计, promote 不挤占配额——修复旧版 max_rounds 失效 bug）。

**每轮步骤**（rn 独立于 tier 递增, 目录 `outputs/<op>/<tier名>/roundN`）：

1. **rebase 检查**：`rn>1 且 rn % REBASELINE_EVERY(10)==0` → `_maybe_rebaseline`：重测 baseline/current/best, 重设基线并同步 best（防环境漂移卡死）；不进 history
2. **设备污染恢复**：`_dev_poisoned=True` 时 `_reset_device`（子进程 sync+empty_cache）
3. **①采集** `_run_optimize`：run_optimize.sh（env 传 TIER + M/N/K——从 kernel config 提取防 512 覆盖）→ 读 diagnosis.json, **无 kernels → 采集失败**。失败 H2：`coll_fail≤1` 回退 total_rounds 重试；`=2` 记 hist 跳过；`≥3` 停止。设备级错误（`_is_device_error` 先排除编译期签名）→ 置 `_dev_poisoned`
4. **首轮基准**：`baseline_ns/num_kernels/num_launches(Σlaunch_count)/baseline_mnk/initial_tflops`（cube_fops 优先, 兜底 2MNK×cube 类 kernel 数）；PyTorch 基准按 `PT_BENCH_MAP` 显式映射（无映射→跳过）；工业级基准 `_load_industrial_best`（actual_mode==mode 才认）缺则 `_auto_run_industrial`；`VERIFY_BASELINE=1` 复测基准（先 rmtree 旧 baseline_verify/）, **复测报正确性失败 → 立即 break（A3）**
5. **尺寸一致性 guard**：当前 M/N/K ≠ baseline_mnk 时告警
6. **②诊断** `_diagnose`：优先复用 run_optimize 的 07 文件（校验含"Per-Kernel 概览"）, 缺失才自算
7. **③.5 Tier2 融合** `_run_fusion`：编译 HIVM MLIR → nga run → 08_fusion/
8. **③.5 分块 sweep**（rn==1 或 tier==3 且 TIER3_SWEEP=1）：在 best_kernel.py 上扫（不碰源）, 最优写回 round_dir 副本, current_kernel 指向它
9. **④Planner** `_plan`：Amdahl 优先级前缀 → planner_context.json → sweep 结论文案 → `PlannerAgent.generate_v4` → plan.md
10. **⑤⑥改码+两段验证**（promote 分支除外）：`for attempt in range(3)`：`_code`（Step0 确定性 → Step1 LLM → 清洗校验）→ 写 round_kernel → 失败 `build_retry_context(stage="code")`；成功 → 验证：段1 `verify_fast_gate`（快测不快于 best → 直接 REVERT）→ 段2 `verify_end_to_end`（warmup+msprof+Event）；验证失败 → `build_retry_context(stage="verify")` + 设备污染标记
    - **采纳（主依据=Event 绝对延迟）**：`evt < best` 或首次对比基线；Event 缺失 → 不采纳（方案A）
    - `kept 且 attempt_log` → `mark_solved` 回填失败库
11. **轮末**：未采纳回滚 current_kernel（内容级恢复 + failed_kernel.py 留证）；NOOP 检测（promote 豁免）；组 hist（含 diag 紧凑串/error_class）；优秀案例记录（`is_excellent`）；best 更新（仅 kept, copy2 best_kernel.py）；`diag_snapshots.jsonl` 追加；`_decide_tier`；promote 轮 `promote_budget+1`；rn+1、`_save_traj`；策略摘要
12. **循环外**：`_write_timing_stats`（六阶段耗时）；vs 工业级比值；`AUTO_CHART` 轨迹图；`final_output/`（kernel_op.py=best_kernel、baseline_kernel.py、final_diff.patch、final_summary.json、REPORT.md）

**停止条件**：有效轮数达上限；连续 3 次采集失败；Tier6 停止/连续无改进停止；源 kernel 正确性失败；基准无法建立。

## 4. 记忆模块 API 全解

### 4.1 failed_cases.py（失败案例库, `memory/tier{N}_failed_cases.json`）
- 常量：`STUCK_AFTER=3`（env FAILED_CASE_STUCK_AFTER）、`MAX_CASES_PER_TIER=50`（env FAILED_CASE_MAX）
- 函数：`cases_path` / `normalize_error`（去行号地址路径数字 → 签名+关键词+sha1[:12] 指纹）/ `classify_error`（**env > code_compile > code_numeric > code_runtime** 四分类, env 不入库）/ `load`+`_save`（损坏→空, LRU 淘汰最久未更新 open/stuck 条目, 永不抛）/ `_find`（fingerprint+stage 双键）
- `record_failure`：命中 attempts+1 + attempted_solutions（去重截 3 条）；**solved 再现 → 降级 open 且 attempts 归 1**（"没根治"语义）；attempts≥3 → **stuck**（只禁原样重试, 不锁新方案）
- `retrieve`：**L1 指纹精确(+100) + L2 关键词交集≥2(+10×交集数)**, 排序 指纹>交集>同op(+5)>solved(+3)>最近, 取 ≤3, 落 hit_count；miss+fallback_all → 跨 tier 兜底
- `format_for_coder`：`[已解决]`（solution/fix_diff）/`[★此路不通]`（stuck 黑名单+禁止原样重试）/`[未解决]`, 均标"★只读参考, 严禁原样复制"
- `mark_solved`：按指纹回填（solution/fix_diff 截 400）
- `build_retry_context`：**scheduler 每轮重试的单一入口**——累积尝试序列 → 本次报错 → **先检索后入库**（防首犯自命中）→ format_for_coder 注入 → record_failure → **负正闭环**：比对优秀案例库（空格归一化匹配 change 摘要, 方案曾成功过 → 提示上下文/尺寸差异勿急着否定）
- 生命周期：`open → stuck(attempts≥3) | solved(成功) →(再现) open`；任何异常吞掉不抛；单进程无锁

### 4.2 excellent_cases.py（优秀案例库, `memory/tier{N}_cases.json`）
- 常量：`EXCELLENT_THRESHOLD=1.3`（env）、`DEFAULT_LIMIT=5`
- `is_excellent(best_before, speedup)`：**相对"上一最优累计加速比"**：`best_before>=1.0 且 speedup > best_before×1.3`
- `record(tier, case)`：同 (op, round) 去重、纯追加；case 含 tier/op/round/strategy/bottleneck/solution/changes[](old/new)/speedup_before/after/improvement_x/ns/recorded_at
- `load(tier, limit)` 取最近 N 条；`format_for_planner` 拼 prompt（截 2500 字符）
- **读写时机**：写 = 轮末 `kept 且 is_excellent`（scheduler.py:2070-2094）；读 = planner 每轮注入 + failed_cases 负正闭环比对

### 4.3 其他
- `memory/codeerror/`：早期 `CodeErrorMemory`（按 kernel 分文件, pattern 子串匹配）**已废弃**, 由 failed_cases 取代（__init__.py 标注）
- `docs/project_knowledge/memory_*.md` 描述的是**模拟器时代旧骨架**（ExperienceStore/RunLog/AB 实验）——文档头声明真机记忆已在 `triton_agent_optimizer/memory/` 落地, **写文档时勿混淆两套体系**

## 6. trajectory / resume 机制

- **主文件**：`outputs/<op>/optimization_trajectory.json`，`{"v":4,"state":{...},"history":[...]}`，`_save_traj` 每轮落盘（state 序列化时把 best 系列键提到最前便于一眼查看, 只重排副本不动引用）。v3 旧文件 → 重置
- **紧凑轨迹**：`planner_trajectory_compact.json`（state 精选键 + `_compact_history(40)`），planner 防 context 膨胀（GLM5.1 预算：100 轮全量 json 可达 50k+ tokens）
- **诊断快照**：`diag_snapshots.jsonl` 每轮追加 `{round,tier,decision,speedup,snapshot}`（审计/讲演用, 不入 context）；history 只存 `_diag_compact` ~120 字符
- **恢复（--resume）**：`traj["state"]["current_kernel"]` 存在且可读 → 从该 kernel 续跑；**Bug 8 兜底**：setdefault `handoff/tier_jumps/promote_budget/last_rebase_round/best_round/best_e2e_ns`, 缺 best_kernel 用 current_kernel 兜底。默认（无 --resume）每次 `_reset_state` 从 round1 重来
- **配套文件**：`best_kernel.py`（best 更新 copy2）、`baseline_kernel.py`、`baseline_verify/`（复测前 rmtree）、`stats/timing_stats.json`、`optimization.log`、`final_output/{kernel_op.py, baseline_kernel.py, final_diff.patch, final_summary.json, trajectory_chart.png, REPORT.md}`。**无独立 state.json**——state 内嵌于 trajectory

## 8. 已知坑与注释警告（完整保留）

1. **msprof 欠采毒 best**（最大教训）：短 kernel 欠采 e2e_ns → 假性 200x；已改 **Event 绝对延迟为 KEEP 唯一主依据**, msprof speedup 仅记录；Event 缺失 → 方案A 不采纳（不退化 msprof 防假值后门）
2. **EVENT_MIN_RATIO 已删除**：曾误伤真实 >10x 轮；Event 真实性由 verify 行数保证（循环异常 → Event=None）
3. **best 绑定 best_kernel**：曾致 113x 代码丢失；现 best 仅 kept 轮更新 + copy2 落盘
4. **设备污染**：verify 崩 AICore（aclrt/575/HIVM/OOM）→ 下轮采集前 `_reset_device`；`_DEV_ERR_EXCLUDE` 先排除编译期错误（vsel/语法/MLIR）, 防坏代码被误判设备污染
5. **H2 采集失败**：重试 1 次（回退计数）→ 跳过 → 3 次停；采集失败不计 no_improve
6. **promote 严格门**：无 evidence 拒绝（曾致轮次白耗+max_rounds 失效）
7. **input 链不变量**：失败轮回滚 current_kernel（同路径内容级恢复+failed_kernel.py 留证）；sweep 只写 round_dir 副本防污染源
8. **计数语义**：total_rounds 含 promote, 有效轮=total−promote_budget（修复 max_rounds 失效）
9. **首轮 M/N/K 必须传真实值**：否则 512 默认覆盖 → baseline 尺寸与 verify 不一致, speedup 失真 64×
10. **per-kernel 取值**：`_get` 只取第一个 kernel 是致命缺陷, 已用 TIER_PER_KERNEL 逐 kernel 列示 + 占比×launch_count（QKV 复用 3 次的低估教训）
11. **失败库"先检索后入库"**（防首犯自命中）；负正闭环比对优秀案例（空格归一化匹配）
12. **context 预算**：GLM5.1 压缩线 140k, compact history 20 轮/紧凑轨迹 40 轮/planner_context `_sanitize_for_ctx` 截断
13. 其他：`_clip` 括号配平防半截表达式；`_summarize_changes` 只按第一个 `=` 切；stub 假 PASS 只允许 stub 模式（生产异常必须 FAIL）；REBASELINE 不进 history（防图点重叠）；诊断占比口径 `单次耗时×launch/total_ns` 统一

**测试锁定**（`test/_sim_flow_test.py`）：cmd 构造（bash/脚本/input_dir/MNK=2048/TIER=3）、decision 序列（KEEP/KEEP/REVERT/KEEP/promote轮KEEP/tier2生效/.../FAIL）、promote 轮原样拷贝、每轮产物齐备、采集链 input 演进、H2 重试跳过停止、F1 ns 反推、F3 tflops、F4 未映射跳过 PyTorch、P1 baseline_verify 清理——**修改上述行为需同步改此测试**。
