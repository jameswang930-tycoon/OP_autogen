## 1. verifier.py 六个函数

### 1.1 `_read_durations(prof_out) -> tuple`（:34）
读 op_summary 产出两种口径耗时。`rglob("op_summary*.csv")` **合并全部分片文件**（msprof 按 `{device}_{model}_{iter}` 拆多文件, 只读首文件会漏 kernel → 假"仅 13 行"）；列名兼容 `Task Duration(us)`/`TaskDuration`、`Op Name`/`OpName`。分类：**op 名以 `aclnn` 开头 = 框架 kernel**（排除）, 其余为目标 kernel。返回 `(目标us和, 全部us和, 目标行数, 总行数)`。求和法稳健性依据：msprof 合并同名连续 kernel 不影响总和。

### 1.2 `_correctness_check(kernel_op) -> (ok, error)`（:77）
子进程跑 `python3 kernel_op.py`, env `KERNEL_LOOP=1, MATMUL_VERIFY=1`（loop=1 加快校验）, timeout 1800s。判据：stdout+stderr 含字面量 `result check: PASS`。报错分类：正则匹配 `error:|Traceback|unsupported op|SyntaxError|not supported|MLIR` → "编译/运行失败（非数值错）"；否则"正确性未通过"。错误文本截断 `[-400:]` 回传 coder。

### 1.3 `verify_fast_gate(kernel_op, round_dir, loop=30) -> dict`（:98）
**两段验证·段1, 无 msprof, 秒级**。先 `_correctness_check`（失败 → `{"ok":False,"error"}` 回传 coder）, 再 `_event_e2e_ns`。返回三态：`ok:False`=编译/正确性失败；`ok:True, e2e_event_ns:None`=Event 不可用（调用方退化全量）；`ok:True, e2e_event_ns:值`=门值（调用方与 best 比较）。

### 1.4 `verify_end_to_end(kernel_op, round_dir, baseline_ns, num_kernels, num_launches) -> dict`（:117）
**段2 全量流程**：
1. warmup `VERIFY_WARMUP`(3) 次裸跑（KERNEL_LOOP=loop 预热 JIT/cache）
2. `_correctness_check` 必须 PASS（防"改错结果还通过"）
3. 一次 msprof（`--ai-core=on`, env `KERNEL_LOOP=loop`, timeout 7200s）
4. **msprof_0 目录每次 rmtree**（防重试残留旧 CSV 被 sorted[0] 误读）
5. **H1 循环自校正**：源码正则 `for\s+\w+\s+in\s+range\(\s*LOOP\s*\)\s*:` 检测 KERNEL_LOOP 循环是否还在。找到 → divisor=loop；**找不到 → divisor = round(n_rows / num_launches)**（用实际 launch 总数非去重数, 防多 launch 算子 ÷ 错虚高）
6. 双口径：`per_pass_us = target_us/divisor`（纯 kernel）, `e2e_per_pass_us = all_us/divisor`（端到端, 无框架行退化为纯 kernel）
7. `speedup = baseline_ns/ns if baseline_ns else None`（显式处理缺失, 不再静默当 1.0）
8. 行数告警：`n_rows < loop` 打警告（不静默）
9. **Event 兜底逻辑**：仅当 `n_rows >= loop`（循环完整=Event 真实）才调 `_event_e2e_ns`, 否则返回 `e2e_event_ns=None` → scheduler 走"Event 缺失 → 方案A 不采纳"防假小毒 best

返回：`ns/e2e_ns/speedup/loop/rows/duration_us/e2e_event_ns`。

### 1.5 `_inject_event_timing(src, rebuild_inputs=True) -> str`（:229）
把 `for X in range(LOOP):` 循环前注入 Event 计时分支：
- 定位标准循环（找不到返回 "" 放弃）
- 扫描循环前缩进≥4 的 `torch.randn?/rand/empty/zeros/ones(` 分配行 → 每窗口重建输入（破 L2, Ascend 无清 L2 API）
- **重建张量必须被 `_keep` 列表持有**（2026-08-13 修复：否则 PyTorch caching allocator 复用刚释放地址 → 窗口2 起 L2 又命中, 实测虚高比值全≈1.0）
- 注入结构：`KERNEL_EVENT_TIME` 触发 → warmup `KERNEL_EVENT_WARMUP`(5) → sync → `KERNEL_EVENT_REPS`(5) 个独立窗口（每窗口包 LOOP 次, 前后 Event record）→ 排序取 **median** → `print('EVENT_E2E_US:%.2f' % (median/LOOP*1000))` → `raise SystemExit(0)`
- 保险：源码无 `import os` 时补一行（防 NameError → 永不采纳 → 误 REVERT）

### 1.6 `_event_e2e_ns(kernel_op, round_dir, loop) -> Optional[float]`（:323）
注入版写入 `round_dir/event_kernel.py`, env `KERNEL_EVENT_TIME=1, KERNEL_LOOP=loop, KERNEL_EVENT_WARMUP=5, MATMUL_VERIFY=""`（计时不算正确性, verify 已先验过）, timeout 1800s；正则 `EVENT_E2E_US:([\d.]+)`, **us×1000→ns**；失败/异常一律返回 None（不阻断主流程）。

## 2. scheduler.py 决策链路

### 2.1 段1 判门（:1853-1881）
`TWO_PHASE_VERIFY=1` 且 `use_llm` 时：`verify_fast_gate` → 快测失败走 FAIL 路径回传 coder；`_fast_evt >= best_e2e_event_ns` → **直接 REVERT**（speedup 用 Event 口径派生, 省掉 warmup+msprof 几分钟/轮）；过门或 Event 不可用 → 段2 `_verify` 全量；msprof 轮 Event 缺失时用快测值兜底回填。

### 2.2 段2 触发条件
过段1门 / 快测异常 / TWO_PHASE_VERIFY=0 / stub 模式。

### 2.3 KEEP/REVERT 判据（:1897-1926）—— ★决策主依据 = Event 绝对延迟
| 情况 | 判定 |
|---|---|
| 有 Event + 有 best | `_evt < _best_evt` 才采纳 |
| 有 Event + 无 best | 与基线 Event 比（`_evt < baseline_e2e_event_ns`, 2026-08-13 修复首次对比, 防假快轮进链）；基线也无 → 无条件建 best |
| **Event 缺失（非晋升轮）** | **方案A：绝不保留**, 不退化 msprof（坏循环兜底测量不可信, 假值毒 best）, 判据文本进 hist.error |

采纳后：`current_speedup=round(speedup,4)`、`kept=True`、可选 SANITY_VERIFY 相邻尺寸检查；KEEP_FLOOR=1.01 用于晋升/无改进轮统计（v3 轨迹 0.97~1.01 噪声教训）。

### 2.4 best 链维护
- `st["best_kernel"]=str(round_kernel)` + `shutil.copy2(round_kernel, kernel_dir/best_kernel.py)`（:2115-2122），**只在 kept 时更新**（REVERT 轮假小 Event 不得毒 best_speedup, 防"加速比 200x 假值"与代码脱钩）
- `best_e2e_event_ns` 更新条件：`_evt_ns and kept and (best is None or _evt_ns < best)`；best_speedup 由 `baseline_event/best_event` 派生（Event 基线缺则 msprof 端到端口径兜底）
- **current_kernel 流转**：轮首快照 `_pre_round_kernel`+`pre_code`（:1798）；未采纳（REVERT/FAIL）→ 回滚到轮首快照, 同路径时**内容快照恢复**（防读到 coder 覆写坏代码, input 链不变量）, 被丢代码另存 `failed_kernel.py` 留证（:1969-1990）
- sweep 写回后 current_kernel 指向 round_dir/kernel_op.py（tier3）；promote 轮原样拷贝不重测 Event（e2e_event_ns=None, 但上游 kept=True 不计入方案A）
- **环境漂移 `_maybe_rebaseline`**：重测 baseline_kernel.py/current/best_kernel.py, **同步刷新 best_e2e_event_ns**（旧值是旧环境绝对最小, 不重置则永久 REVERT 卡死）, rebase 不进 history

### 2.5 hist 记录（:2038-2060）
round/tier/strategy/expected_impact/change/changes_full/speedup/kernel_speedup/prev_speedup/ns/e2e_ns/**e2e_event_ns**/decision(KEEP|FAIL|REVERT)/result(OK|FAIL|NOOP)/sweep 三态/error(**error_class 四分类**: env/code_compile/code_numeric/code_runtime)/**diag**（`_diag_compact` 紧凑串 ~120 字符, 全量写 `diag_snapshots.jsonl` 每轮追加不入 context）。`_diag_snapshot` 每 kernel 记 `{pct(=dur×launch/total), bn, cu, mu, l2, redun, eng top2}`。NOOP 判定跳过 promote 轮、REVERT/FAIL 用回滚前事实。

### 2.6 vs_industrial
`_load_industrial_best`：各 mode json（time_us=median、actual_mode==mode 才认）取最小；缺则 `AUTO_RUN_IND_BENCH=1` 自动跑。最终 `our_best_e2e_event_ns`（best_round 轮 Event 实测, 缺则 `baseline_event/best_speedup` 反推）÷ `industrial_time_us×1000` = vs_industrial_ratio（<1 快于工业级）。

## 3. pipeline_parse_task.py 的验证相关

`parse()` 端到端求和（:337-343）：`total_ns = Σ(非aclnn kernel 的 task_duration_us)×1000`——与 verifier 目标口径一致；kernels[] 每行一次 launch；`kernel_slots` 按 distinct Op Name 去重（launch_count 累加）；framework 判定 `name.lower().startswith("aclnn")`；`num_kernels` = 非框架去重数（行数检测基准）；per-pipe 列归一化（aic_cube 缺用 mac、cube mte3 缺用 aiv_mte3）；L2 hit 归一化 0~1。

## 4. test/measure_final_event.py（最终测量）

- `_inject(src, warmup, reps, pipelined)`：与 verifier 同构但**每窗口只测 1 次完整调用**（host 下发开销全额计入, 与工业级每次 fn(i) 同构）；`--pipelined N`（**默认 10**）时窗口内套 `for _p in range(_PIPE)` 连续 P 次 ÷P（流水隐藏 host ≈纯设备, 与 bench --pipelined 同构）
- `FINAL_EVENT_E2E_US:%.2f` 直接打印 us（**不 ÷LOOP, 不 ×1000 换算**——注意：`elapsed_time` 返回 ms, 打印值=median/`_PIPE`×1000 已换算）
- 写回 `_write_back`：正则 `("op":)None → "op":{us:g}` 替换 bench_all.py 的 OUR_RESULTS_US
- 默认 `--rep 30 --warmup 10 --pipelined 10`, env FINAL_EVENT_WORK/TIMEOUT(1800)/WARMUP/REPS/PIPE, `KERNEL_LOOP=1`
- conv2d/conv_bias_relu 的 unfold 派生张量不在重建范围（已知局限注释）

## 6. 假加速比防护链（完整 7 道）

1. **循环丢失**（coder 弄丢 range(LOOP)）→ 源码正则检测 + 实测遍数自校正 + 行数<loop 告警
2. **循环异常** → Event 不测（None）→ 方案A 不采纳
3. **msprof 欠采假 200x** → Event 主依据 + best 只在 kept 更新
4. **L2 复用虚高** → 每窗口重建输入 + `_keep` 防 GC 复用
5. **重试残留 CSV** → msprof_0 rmtree
6. **旧 best Event 环境漂移** → rebase 时用 best_kernel.py 复测同步
7. **EVENT_MIN_RATIO 比值拦截已废弃**（曾误伤 naive→tl.dot 真实 >10x）, 2026-08-12 简化后**循环完整性即 Event 真实性唯一保证**
