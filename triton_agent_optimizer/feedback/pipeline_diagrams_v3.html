Scheduler 主循环

每轮五步闭环（Round1 → N）
采集 → 决策 → 改码 → 验证
① 采集+解析
通用 msprof + 逐 kernel msprof op（双源）
→ task.json · board_N.json · diagnosis.json
  • 骨架：每 kernel 耗时 / launch / api 开销
  • deep：带宽 / L2 / cube·vec 占用 / 冲突
  • roofline 用 hardware_peak.json 实测峰值校准
② 分块 sweep（Tier3）
best_kernel 上枚举 L0 合法 BLOCK，Event 实测取最优
→ 09_tier3_sweep/sweep_result.json
  • L0A/B≤64KB、L0C≤128KB、全部 2 的幂
  • BLOCK_K ≥ K_OUT 保底（半吊子块拒收）
  • 写回 round_dir 副本（不碰 input 源）
③ Planner（LLM）
读字段+轨迹+手递+优秀案例 → changes[] + promote 决策
→ plan.md + 10_tier_handoff.json
  • 输出 old→new 精确替换片段（LLM 只决策）
  • promote 必须带数据依据（evidence）
④ Coder（确定性）
old→new 精确替换 + 语法/函数完整校验
→ roundN/kernel_op.py + diff.patch
  • 确定性字符串替换，杜绝 LLM 乱改
  • 失败回传报错给 Planner 同轮再改
⑤ Verifier
正确性 + msprof 端到端双口径 + Event 设备侧权威计时
→ e2e_event_ns + trajectory history
  • MATMUL_VERIFY=1 对 torch 参考校验
  • Event 多窗口 median + 输入轮换破 L2
  • 循环异常 → 不测 Event → 方案不保留
核心主张：真机数据驱动 → 确定性优于生成 → 测量纪律（Event 绝对延迟权威值）

严格最优门

KEEP / REVERT
Event 绝对延迟 < 历史最优才保留
KEEP — 严格最优
Event 绝对延迟 < 历史最小才采纳（含首次对比基线），best_kernel.py 更新 + best_round 绑定
  • Event 缺失（循环异常）→ 不采纳
  • 防 msprof 欠采假快轮进链
REVERT — 回滚
失败/无改进恢复 best_kernel（内容快照），failed_kernel.py 留证
  • diff.patch 不被失败尝试覆盖
  • input 链不中断（轮首快照恢复）
假小防护：循环被改坏（msprof 行数 < LOOP）→ 不测 Event → 方案不保留

层间决策

promote / 回退 / 停止
6 层策略逐层推进
promote → Tier+1
必须带数据依据（promote_evidence），否则本层再优化；手递 handoff 传瓶颈+方向
回退 → Tier-1
判瓶颈属前层且有空间 → 跳回重新诊断
停止
Tier6 连续 3 轮无改进 / 跑满 max_rounds / 采集连续失败 3 次
防呆机制：同跳转路径 ≥3 次拒绝（防死循环）· 每 10 轮 REBASELINE 校正环境漂移 · 设备污染自动重置

6 层优化策略

Tier1 算法 → Tier6 配置 · 每层一个 Round 五步闭环
Tier1 算法
单遍 / 剪枝 / im2col 走 cube（收益最大）
例：conv 外积 → tl.dot
Tier2 融合
跨 kernel 合并（HIVM MLIR 分析）
例：conv+bias+relu 3→1
Tier3 分块
sweep 枚举 L0 合法 BLOCK 实测择优
例：(BM,BN,BK) 全枚举
Tier4 访存
连续化 / 对齐 / burst
例：innermost stride=1
Tier5 计算
指令级：除法→rsqrt 乘链
例：/sqrt → *rsqrt
Tier6 配置
调度/流水/资源收尾，3 轮无改进停止
例：grid 调度
轮次经济：promote 轮不改码且不耗 max_rounds 配额；达标（--target）不硬停，继续探层
